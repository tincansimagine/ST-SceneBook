# 0.3.0 프롬프트 재검토

## 0.4.5 형식 복구 보강

- 사용자 요청으로 라이트보드 4.1의 `lb.onValidate`, `lb.repair`, `gen`의 복구 호출 경로, 4.4·4.5의 `onValidate`와 출력 스키마를 다시 확인했다. 4.1은 이스케이프·공백·들여쓰기 정리 후 재해석하며 실패하면 별도 AI 복구 패스를 사용한다. 4.4·4.5는 파싱 후 구조·필드·장면 위치 오류를 모아 보고한다.
- 씬북은 자체 JSON 계약에 맞춰 **원문 해석 → 로컬 형식 복구 → 타입 정리 → 장면별 검증**으로 구성했다. 참고 확장의 복구 프롬프트·코드는 복제하지 않았다. 범용 JSON 복구는 별도 ISC 라이선스 모듈 jsonrepair를 출처와 함께 사용하며 자동 복구 시 추가 AI 호출은 없다.
- JSON 출력 규칙을 실제 주입 프롬프트와 수동 분석 프롬프트의 끝에 덧붙인다. 배열·숫자 타입, 인용·개행 이스케이프, 필드/배열 사이 쉼표, 전체 구조 닫기, 토큰이 부족할 때 묘사를 줄여도 구조는 완성하기를 명시한다. 사용자 저장 문자열은 변경하지 않고 편집기에서 추가 규칙을 볼 수 있다.
- 여러 장면 중 검증에 실패한 장면은 원문·이유를 남기고 나머지 정상 장면을 처리한다. 불명확한 삽입 위치를 임의 추정하지 않는다. 이번 변경은 사용자의 요청에 따라 추가 테스트 없이 제공한다.

## 추가한 기본 지시문

`src/prompts.mjs`의 기본 템플릿은 장면 후보·한 순간·등장자·카메라·환경·인물 동작·복장 연속성·좌표·사용자 가중치를 각각 다룬다. 무조건 복잡한 구도나 다량의 신체 묘사를 요구하지 않는다. 불명확한 설정을 눈에 띄는 소품이나 외형으로 임의 보충하지 않는다. 요청하지 않은 네거티브를 보이지 않는 요소에서 추론하지 않는다.

`{{data}}`, `{{maxScenes}}`, `{{modelRule}}`, `{{playerRule}}`, `{{direction}}` 변수는 문자열로 한 번만 치환한다. 채팅에 동일한 매크로 문자열이 있어도 재실행하지 않는다. 템플릿은 JS로 실행되지 않는다. 커스텀 지시문에는 `{{data}}`가 있어야 하며 기존 JSON 응답 스키마를 유지해야 한다.

사용자가 저장한 `analysisPrompt`가 있으면 이를 사용한다. 빈 값은 현재 기본 템플릿을 의미한다. 기본 지시문 불러오기는 편집기에만 반영되며 적용·저장 전에는 사용자 설정을 바꾸지 않는다. 공유 JSON은 프롬프트 필드만 포함하고 API 키·채팅·인물 라이브러리를 포함하지 않는다.

## 검증과 한계

- 템플릿 치환, 가중치 보존, 모델 분기, 공유 파일 필드 제한, 장면별 최종 프롬프트와 공통 태그 분리 테스트.
- 브라우저에서 최종 프롬프트 수정 → 초안 저장 → 다시 열기 → 가상 생성 요청의 문자열·인물 순서·좌표·시드 설정 확인.
- 실제 LLM의 출력 품질과 NovelAI 이미지 품질을 비교 평가한 결과는 아니다. 이번 작업에서 유료 API를 호출하지 않았다.
- 콜라주·만화 패널·키비주얼, 태그북 검색 등 레퍼런스의 다른 기능을 구현한 것으로 주장하지 않는다.

## 0.4.3 실제 주입 기본 프롬프트

개선 대상은 `src/injection.mjs`의 `DEFAULT_INJECTION_PROMPT`다. 자동 생성에 쓰이지 않는 별도 분석 프롬프트만 개선하는 구조를 바로잡았다. 저장된 `injectionPrompt`가 있으면 그 값을 사용하며 기본 지시문 업데이트가 커스텀 문자열을 덮어쓰지 않는다.

- AutoPic의 허용된 캐릭터 식별자, 등록 외형 자동 합성, 미등록 인물의 완전한 묘사 원칙을 씬북의 JSON 구조에 맞춰 적용했다. 미등록 인물의 `appearance`를 실제 이미지 프롬프트에 합성한다.
- 라이트보드 4.1의 필드 분리·강조 보존, 4.4의 행동 주체·상대·화면 구성, 4.5의 자연어/태그 경로와 단일 순간·필드 책임을 주입 지시문에 반영했다.
- CSP의 중요 정보 우선·짧은 표현·공통 프롬프트 중복 방지·구도 모순 방지 원칙을 반영했다. 복잡한 구도나 임의의 표정·접촉을 강요하지 않는다.
- 현재 복장과 기본 복장을 구별한다. 기본 복장이 유지되면 outfit을 생략해 저장값을 사용하고, 변경됐다면 그 순간 보이는 전체 복장을 작성한다. 등록 외형과 사용자 가중치는 코드에서 보존한다.
- 생성된 삽화 지시가 없으면 자동 처리는 끝난다. 잘못된 지시는 오류를 알리고 추가 AI 분석을 자동 실행하지 않는다. 수동 분석을 명시적으로 선택하면 기존 분석 템플릿을 사용한다.
- 상단 프롬프트 버튼은 기본/사용자 주입 지시문을 직접 연다. 적용·공유·기본 지시문 불러오기를 제공한다. 적용하면 저장되며 별도 설정 저장 버튼이 필요하지 않다.

실제 LLM과 NovelAI 계정으로 프롬프트 품질을 비교 평가한 것은 아니다. 구조·값 보존·호출 수와 UI 동작은 단위 및 브라우저 테스트로 확인한다.
